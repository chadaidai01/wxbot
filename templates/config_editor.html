v3.0测试版喵

本地数据监听（WeFlow）

底层监听改为轮询 WeFlow（UserDataIsSafeFromUsers）的 HTTP API，读取微信4.x本地数据库来"看"新消息，取代 wxauto 窗口监听；发送消息仍由 wxauto 完成。
需先在 WeFlow「设置 → HTTP API」中开启，并确认端口。
与 WeFlow 设置中的访问令牌保持一致；留空则无需校验。
防止启动时回灌历史记录。

剧场系统（HDS-Interlude 引擎）

剧场引擎是 hds-interlude 1.0.1-beta6-rebuild 的 Python 移植版（hdsi/）： 每段聊天/群聊维护一部持续上演的生活剧本，包含幕间推进、对话后续、到期意图、承诺回访、 情绪偏移（Alter）、行动窗口（Agency）、日程预判与记忆压缩。数据保存在 Theater/hdsi.sqlite3。

① 引擎与模型

开启后，勾选「剧场」的聊天由 hdsi 引擎接管叙事与投递。
存放 hdsi.sqlite3（与上游表结构一致）；旧版 *.json 会在首次打开记忆编辑器时归档到该目录的 _legacy_json_backup/。
建议用稳定的文本模型（如 deepseek-chat）；留空则用主模型 MODEL。
思考型模型会先消耗一部分预算推理，再写 JSON 合约（剧本+结构化字段），建议 8192~16384。留空/0 回退到 MAX_TOKEN。
JSON 结构稳定性优先时建议 0.8~0.9；温度越高越放得开，也越容易跑格式。

② 节奏与推进

映射上游 runtime.autoAdvanceIntervalMinutes：没有消息时角色按真实时间生活。
映射上游 runtime.restWindows：安静时间内降低推进频率、不主动投递。
映射上游 runtime.conversationFollowUpMinutes（默认 10、20 分钟各补写一次对话余波）。
映射上游 timelineDirector.enabled：自动推进前先由轻量模型生成时间账本，失败自动降级。

③ 叙事与记忆

映射上游 runtime.contextEntryLimit：每次写作读取的近期剧本条目下限。
映射上游 memory.recentEntryLimit：主叙事读取的最近原始条目数。
映射上游 memory.enabled：旧剧本后台压缩成前情摘要 + 在场表，并沉淀长期事实。
映射上游 memory.activeConsequenceDefaultStrength：谈话/事件在之后几轮里的持续影响程度。

④ 情绪（Alter）

映射上游 alterSystem.enabled：氛围净变化累计超过阈值后，生成临时情绪偏移注入后续写作。
映射上游 alterSystem.baseThreshold。

⑤ 主动联系（Agency Window）

映射上游 agency.enabled + runtime.allowProactiveMessages：生活产生真实理由后，经日程/隐私/设备容量判断再决定立即联系、稍后重查或自然放下。
映射上游 runtime.proactiveWillingnessThreshold（按 0-1 换算）。
映射上游 agency.minimumProactiveIntervalMinutes；承诺型联系可绕过。

⑥ 日程（Schedule Preplan）

映射上游 schedulePreplan.enabled：后台每日审查周规律 + 日期例外，主叙事只读取未来约 12 小时。
映射上游 schedulePreplan.reviewAfterLocalHour。
映射上游 schedulePreplan.variationLevel。
映射上游 schedulePreplan.anchorAutoAdvance：上课/到校等固定日程边界可作为推进锚点。

⑦ 群聊

映射上游 onebot.groupChats[].contextLimit：每次群叙事附带的最近群消息条数。
映射上游 groupChats[].willingness（默认关闭）。关闭时所有群消息都进入群聊缓冲；开启后未@消息按本地分数决定是否调用主模型，@机器人始终直接通过。
映射上游 willingness.threshold（0-1）；大于 1 的旧值会被忽略并使用上游默认 0.24。
映射上游 willingness.decayHalfLifeSeconds。

    群聊消息接收配置

    启用后，当机器人在群聊中被@时会作出回应。此选项在"接收所有群聊消息"模式下无效。
    启用后，当群聊消息包含下方设置的关键词时，机器人会作出回应。
    多个关键词请使用英文逗号 (,)、中文逗号 (，) 或空格分隔。机器人会根据这些关键词判断是否回应。
    设置机器人在满足回复条件（被@、关键词触发或接收所有消息）时实际做出回复的概率。100表示总是回复，0表示总不回复。
    与上方"群聊回复概率"完全独立：未@、未命中关键词时，按此概率主动回复群友消息。复读机和消息轰炸不受此概率影响。
    启用后，如果群聊消息触发了关键词回复，将无视上方设置的"群聊回复概率"，必定进行回复。此选项优先于"群聊回复概率"。

    提醒管理 (修改后重启Bot生效)

    指令设置

    开启后，可在聊天中直接发送以下以“/”开头的指令进行控制。

    可用指令说明

    • /重启 或 /re：重新启动程序（将先保存必要数据再重启）。
    • /总结 或 /ms：立即进行一次临时记忆总结成记忆片段（无论记忆功能是否启用）。
    • /关闭主动消息 或 /da：关闭主动发消息功能。
    • /开启主动消息 或 /ea：开启主动发消息功能。
    • /清除临时记忆 或 /cl：清理当前聊天窗口对应的短期上下文与临时记忆。适用于AI回复出现异常（如乱码或思维链）时使用。
    • /允许语音通话 或 /ev：允许使用语音通话进行定时提醒（仅私聊提醒有效）。
    • /禁止语音通话 或 /dv：禁止使用语音通话进行定时提醒。

    定时重启Bot配置

    ⚠️ 自动重启功能已禁用，以下设置无效。
    此功能为实验性功能，启用后允许程序在满足特定条件时自动重启，以期解决长时间运行可能导致的性能下降和回复变慢问题。重启前会自动保存聊天上下文及提醒列表。
    开启后，程序将根据下方设定的条件尝试自动重启。
    当程序连续运行达到此设定的时长后，将开始检查是否满足重启的不活跃条件。例如，设置为 2.0 表示运行 2 小时后检查。
    当程序运行达到上述时长阈值后，如果在这段时间内没有任何消息接收或机器人主动活动（持续达到此分钟数），则执行重启。例如，设置为 15 表示需要持续 15 分钟无活动。
    注意事项：
    • 定时重启会中断所有正在进行的处理，包括未完成的对话和消息队列。
    • 通过配置编辑器修改的设置需手动重启才能生效，定时重启不会自动应用这些更改。
    • 定时重启会自动避开定时提醒，防止重启期间遗漏提醒。
